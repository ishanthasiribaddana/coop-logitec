Risk Assessment

Risk Matrix

12 identified risks with probability, impact, severity, and mitigation strategies

#RiskProbabilityImpactSeverityMitigation Strategy
R1 Poor network connectivity in field areas High High Critical Offline-first architecture with SQLite local DB, sync engine with idempotency keys, conflict resolution via server-side validation
R2 User adoption resistance (Sales Reps, Delivery) Medium High High Intuitive mobile UI (< 5 taps for order), training programs, phased rollout starting with tech-savvy reps, feedback loops
R3 Data loss during offline sync conflicts Medium High High Timestamp-based conflict resolution, idempotency_key dedup, server-side inventory re-validation, sync_log for audit
R4 Payment fraud or misappropriation Low High High GPS-tagged payments, daily_collection_summary with variance tracking, dual verification workflow, audit_log on all financial ops
R5 WildFly monolith performance bottleneck Medium Medium Medium Redis caching (Jedis) for hot data, MariaDB read replicas for reports, JPA query optimization, connection pooling
R6 Scope creep during development High Medium High Phased delivery with clear milestones, strict change management, feature flags via system_configuration, MVP-first approach
R7 JasperReports PDF generation latency Medium Low Medium Async PDF generation via EJB @Asynchronous, pre-compiled .jasper templates, Redis caching of generated PDFs
R8 Mobile app compatibility issues Medium Medium Medium React Native cross-platform, minimum OS versions (Android 8.0+, iOS 14.0+), device testing matrix, OTA updates
R9 MariaDB data growth / query performance Low Medium Medium Table partitioning for gps_tracking_log and audit_log, archival strategy, proper indexing, query profiling
R10 WhatsApp API rate limits / downtime Medium Low Low Fallback to SMS/Email, message queue for retry, Meta WhatsApp Cloud API rate limit monitoring
R11 Security breach / unauthorized access Low High High JWT with short expiry + refresh tokens, BCrypt hashing, RBAC with granular permissions, TLS 1.3, audit_log, IP whitelisting
R12 Key personnel dependency Medium Medium Medium Documentation, code reviews, knowledge sharing sessions, modular codebase with clear separation
Process Flows

Key Business Processes

End-to-end flows showing how data moves through the system

🚚 Order-to-Delivery Flow

1. Sales Rep checks in at shop route_plan_stop
2. Browses catalog, checks stock distributor_product inventory
3. Collects order (offline) sales_order
4. Submits → Distributor reviews
5. Approved → Inventory reserved inventory_movement
6. Assigned to delivery trip delivery_trip_order
7. Warehouse loads vehicle vehicle_inventory
8. DN voucher generated voucher (DN)
9. Delivery confirmed delivery_confirmation
10. Invoice generated voucher (INV)
11. Payment collected payment
12. Order → COMPLETED

💰 Payment & Ledger Flow

1. Invoice generated after delivery voucher (INV)
2. shop_ledger: DEBIT entry posted shop_ledger
3. Payment collected (Cash/Cheque/UPI) payment
4. Receipt voucher generated voucher (REC)
5. Payment allocated to invoice payment_allocation
6. shop_ledger: CREDIT entry posted
7. Daily collection summary submitted daily_collection_summary
8. Distributor verifies & reconciles
9. Payment: COLLECTED → VERIFIED → DEPOSITED
10. If cheque bounced → DEBIT reversal
11. If overdue → notification sent
12. Credit limit checked for new orders

🗃 Inventory Flow

1. Vendor ships goods goods_received_note
2. GRN verified → stock increases inventory
3. Batch created inventory_batch
4. Order approved → qty reserved
5. Loaded onto vehicle → qty decreases vehicle_inventory
6. Delivered → vehicle inventory decreases
7. Returns → stock restored delivery_return
8. All movements logged inventory_movement

📋 Voucher Lifecycle

1. Trigger event (delivery, payment, return)
2. Next number from sequence voucher_number_sequence
3. Voucher created with line items voucher + voucher_line
4. Tax summary calculated voucher_tax_summary
5. PDF generated (JasperReports)
6. Sent via Email/WhatsApp/SMS/Print
7. Status: GENERATED → SENT
8. For INV: SENT → PARTIALLY_PAID → PAID
9. Past due_date → OVERDUE
10. Credit Note links via parent_voucher_id
Environment

Operating Environment & Constraints

📱 Client Requirements

  • ✓ Mobile: Android 8.0+ / iOS 14.0+
  • ✓ Web: Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
  • ✓ Smartphones: GPS and camera required
  • ✓ Connectivity: Intermittent (offline-first design)

🛠 Design Constraints

  • ✓ Monolithic architecture — single WAR on WildFly
  • ✓ Jakarta EE 10 standards (JAX-RS, EJB, JPA)
  • ✓ PCI-DSS compliant payment processing
  • ✓ Multi-currency and multi-language support
  • ✓ GPS privacy regulations compliance
  • ✓ Tax compliance (GST/VAT configurable per region)
